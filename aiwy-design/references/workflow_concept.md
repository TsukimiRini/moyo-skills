# Phase 1 workflow — Concept (立项)

The output of this phase is `00_concept.md` (filled per schema) + first checkpoint in `decisions.md`.

## Grilling tree

Process top-to-bottom. For each node, **state recommended answer + reason** so user can confirm / redirect quickly. One question at a time. Don't proceed until current node is answered.

### 1. 一句话钩子
- Goal: 把整个游戏压缩到一句话。如果用户的钩子超过 30 字，挤一挤。
- Bad: "玄幻冒险，多女主"
- Good: 一句话能讲清核心情感动力 + 设定的 — 不能用万金油形容词凑出来
- 不通过条件: 没有动力 / 没有 stakes / 全是名词。

### 2. 题材标签 (2-6 个)
- 从钩子里抽 + 用户补。
- 推荐询问句式: "我从钩子里看到 [病娇 / 校园 / 姐弟]，再加 1-2 个能定基调的标签？" 例 "心理悬疑" / "都市黑童话" 之类。

### 3. 参考作品 (2-3 个)
- 不是"我喜欢"，而是"我借鉴这个游戏 / 番 / 小说的某个具体方面"。
- 每条要写"借鉴什么 / 不借鉴什么"。
- 例: "《YYY》——借鉴它的毒舌台词节奏；不借鉴它的真结局形式（我不要梗在最后一刻反转）"。
- 如果用户只给名字没说借鉴点，问回去。

### 4. R18 等级 (none / suggestive / medium / explicit)
- 早问，因为它影响 character schema 是否启用 sexual_* 字段。
- 默认推荐基于 (3) 的参考作品: 如果参考的是工口向 / 乙女 18+ 作品，medium 起步。
- 如果不确定，问"你之前给我看的角色案例里 sexual_experience 写得很细，那应该是 explicit?"

### 5. 红线 (≥ 3 条)
- "这个项目绝不会做的事"。
- 推荐起手三条 ("不写圣母光环 / 不允许角色 OOC 转向 / 不写 BE")，让用户改。
- 红线越具体越管用。"不写 BE" ✓ vs "不写让人不爽的剧情" ✗.
- 这条会被下游每次出文 self-check，所以认真聊。

### 6. 玩家锁定维度
- "玩家代入的角色，哪些维度玩家不能自定义？"
- 默认: 性别可自定义、姓名可自定义、外貌不可见。
- 锁的常见情况: 故事强需求（必须是某个特定身份/亲属/职业），跟攻略对象的关系是固定的。
- 每个锁定项要写"why must lock" — 解锁后哪个角色的人设会崩。

### 7. 主玩法骨架 (粗粒度)
- 一段 100-300 字描述。**不写状态机数值**，那是 interface 阶段 / 平台蓝图的事。
- AI 文游里"剧情"由 runtime AI 动态生成，玩法骨架描述的是**runtime 之外的"框架层"**：玩家通过什么界面互动、什么状态在跟踪、好感度怎么涨、怎么触发关键事件。
- 应该回答: 玩家有哪些界面可以进出？时间 / 资源结构？好感度 / 状态怎么变？多结局机制？
- 例: "由手机消息界面 + 线下对话界面交替推进；每天 3 个对话窗口（早 / 午 / 晚）由 AI runtime 自由生成；好感度由 AI 在每次对话后自评 0-100 给分，超过阈值解锁新事件；主线锁需要在 30 天内攻略至少一人到 80。"

### 8. 攻略对象差异化轴 (女性向必填)
- "你的攻略对象之间最根本的区别是什么？"
- ✗ 不要"外貌 / 性格" — 这是表面 axes
- ✓ 要"性格起点 / 玩家在他眼里的身份 / 关系起点 / 弱点机制" — 这是结构性 axes
- 例: "差异化在 (a) 关系起点（亲弟 / 学长 / 陌生人），(b) 玩家在他眼里的角色（妹妹 / 救命恩人 / 猎物），(c) 攻略主旋律（驯化 / 救赎 / 拉拢）"

### 9. 玩家嗑点
- "为什么玩家会嗑这游戏？" 用具体词: "甜宠 / be 美学 / 强强 / 追妻火葬场 / 病娇 / 救赎 / 兄妹 / 双向暗恋"
- 一个项目可以有 2-3 个嗑点；不要列 8 个，太散。

### 10. 已知机制（特殊设计）
- 隐藏路线？真结局？沉默主角？姓名可改？多人攻略边界（同时只能一个 / 自由）？
- 默认回收 (7) 主玩法 提到的机制，问 "还有别的吗？"

### 11. 写作示范段 (≤ 200 字)
- 用户给一段他想要的写作语气 demo。可以是小说节选 / 角色独白 / 对话片段。
- 如果用户没现成的，问 "你之前的项目有没有写过你满意的段落？给我贴一段。"
- 实在没有，让用户口述一个场景，我替他写一版，他改到满意为止 → 锁定。

### 12. 视觉风格关键词 (≥ 3 个 Danbooru / mid-journey 风格 tag)
- 给 NovelAI 全局 prefix 用。
- 默认推荐基于参考作品的视觉风格反推。
- 例 (近未来都市风格): `anime style, soft watercolor lighting, muted palette, detailed line art, cinematic composition`

### 13. 主要角色清单
- 仅列代号，不展开。详情在 Phase 2 grill.
- 例: ["<角色 A> (身份/标签)", "<角色 B> (身份/标签)", ...]

## 当 12+1 走完 → 写 `00_concept.md`

把答案填到模板。**完整保留用户给的写作示范段原文**，不要复述；这是下游写对白的锚点。

## 锁定
- 跟用户走查 `00_concept.md` 一遍, 5 必产出都填了, 玩家锁定 / R18 / 主玩法骨架都有
- 必须 PASS（无 FAIL）才让用户 `/aiwy-lock concept`
- WARN 可以暂时忽略，但提示用户

## 锁定后产出 decisions.md 第一条
- `lock.py` 自动生成日期条目
- key_decisions 字段填: 题材 / R18 / 玩家锁定 / 红线（关键 3 条）/ 嗑点 / 玩家差异化轴

进入 Phase 2 (Characters)。
